Version: 0.6.0
Date: ????-??-??

  Changes:
    - gvv file restructuring: core files moved from modules/ to core/ (core/utils/, core/datas/).
    - Ritn mods architecture (step 1): core/defines.lua path registry (gvv.defines), core/class.lua class factory, core/setup-classes.lua, core/modules.lua sent to __core__ event_handler. load.lua and gui_event.lua become modules (modules/events.lua, modules/player.lua, modules/gui_event.lua). No behaviour change.
    - Ritn mods architecture (step 2a): library sorted by part in lualib/ : lualib/common/ (util, table_to_str, sprite, luaobj_prop, copy_code, doctor), lualib/api/ (attribute_type_map, concept_fields), lualib/remote_code/. No behaviour change.
    - lualib/common/check.lua: value checking functions modelled on RitnLib (isNil, isEmptyString, defaultValue, startsWith, isTable, isEmpty, isLuaObject, isValidLuaObject, dataType, tryGet, getPath, tryCatch...), standalone copy with fixes. Not used yet.
    - Ritn mods architecture (step 3.0): GUI foundation copied and adapted from RitnLib 0.10.7 (source noted in each file): classes/GvvPlayer.lua, classes/GvvGui.lua (actions call class methods directly), classes/GvvGuiElement.lua (gui_name-type-name names, tags). modules/gui.lua dispatches GUI events to migrated windows first, then to the old code, now in legacy/ until it is migrated. Console commands registered by modules/commands.lua (add_commands). No behaviour change.
    - Ritn mods architecture (step 3.1): main window rebuilt by classes/GvvGuiMain.lua and gui/main.lua with gvv_main-type-name element names (open, close, toggle, resize, tab change). Tab contents are still built by the old code (legacy/gui.lua build_* functions). New core/migrations.lua: the 0.6.0 migration closes the old gvv windows and clears the old element references (data kept); it replaces the 0.4 migration.
    - Ritn mods architecture (step 3.2): gvv small windows (dump, input code, copy code, edit code, export, import) rebuilt by classes/GvvGuiDialog.lua and gui/dialogs.lua with gvv_dialog-type-name names; read-only texts keep their original text in element tags instead of a hidden label. Same behaviour as before (Escape, close button, closing with the main window or on main window click).
    - Ritn mods architecture (step 3.3): help tab rebuilt by classes/GvvGuiHelp.lua, gui/help.lua and gui/help_pages.lua (pages content, same texts) with gvv_help-type-name names; legacy/help_menu.lua removed. Texts to copy are read-only through element tags.
    - The main gvv window now opens centred on screen (it used to open in the top left corner).
  Bugfixes:
    - Help tab diagnose / fix and remote.call(..., "c", ...) failed with "function diag ... is not found" for mods loading gvv through require("__gvv__.gvv")(): diag, fix and c were missing from that interface since 0.5.x. Restored, built from the console code templates.
    - /gdump-json produced invalid JSON: apostrophes and some control characters were escaped Lua-style (\', \a, \v), inf/NaN and functions were written raw. Strings are now escaped per JSON rules, inf/NaN become null, functions become "function".
    - /gdump-luaon produced invalid Lua: reserved words used as keys (end, for...) are now written ["end"], inf/NaN as math.huge and 0/0, functions as "function".
    - Converting a table that references itself no longer crashes with a stack overflow: "<recursive table>" is written instead.
    - Deep copy (search results, tracking list, docked object paths) now uses Factorio util.table.deepcopy: no crash on recursive tables, original metatables kept.
    - LuaObject properties: reading methods is now protected like attributes (no error on an object that became invalid), a missing sub-object (nil) no longer crashes, read values are no longer modified (object_name injection), dead concept code removed.
    - Lua objects tab: refreshing or registering an object that no longer exists (e.g. destroyed entity) raised "attempt to index local 'obj' (a nil value)" at tree.lua. A clear message is now shown: "That LuaObject is not there anymore." with the object path, and the object is removed from the tab list.
    - Variable tracking: moving entries up/down, importing a list and confirming an entry edit raised "table index is nil" (variables i/value left undefined by a rename in 0.5.x). Fixed.
  Published:
    - Ritn

    - arg1, arg2, arg3, ... will become local arg = {arg1, arg2, arg3, ...} inside of script.

Version: 0.1.1
Date: 2020-09-05

  Changes:
    - Remote code(Which I recommended to paste in remote mod/map's control.lua) is changed to shorter code referring the code inside of gvv mod. Then it doesn't need to update your remote code by hand anymore when gvv provide updated remote code. Thanks for giving me this idea.
    - Added guide text that suggesting how to handle remote code at "control.lua" help page. Shortly explaining a way to put it anywhere.

  Info:
    - Remote code will be a function when called by require. Mods or map can freely decide whether to run the code to register gvv interface now or later or not. "now" is just having "()" brackets after require(...) function, like "require(...)()". For "later", you need to assign it to a local value first like "local something = require(...)".
    - Remote code from 0.1.0 will work fine for now. No changes to it, but it is recommended to change it to code of 0.1.1. Then no further by hand.
    - Still you can get raw remote code from "Helper" - "Console command - 1" page. Just delete leading "/c ".

  Fixes:
    - Fixed changelog.txt to be parsed correctly.
    - Fixed error message shown when /gdump <modname> failed due to demand mod is not supporting remote interface is shown as the message of map.
    - Fixed /gmods not showing an interface registered mod in list if global table of that have errorful entry in its global table.
